## 3. SEO migration

Every collection entry has a `seo: { title, description }` block. Sources:

- **Courses / case studies / sectors / locations / blog**: copied verbatim from the old `meta.title` and `meta.description` fields in the Next.js TS files, which were themselves extracted from WordPress (Yoast `wp_yoast_indexable` table) during step 1 → step 2.
- **About / FAQs / index pages**: written specifically for the new pages using the same voice; descriptions kept under 160 chars.
- **`<title>` formatting**: `BaseHead.astro` applies `buildTitle()` which appends `" — International Training and Development"` unless the title already contains the site name.
- **JSON-LD**:
  - `Organization` and `WebSite` schemas are emitted on every page from `BaseLayout` (built from `src/lib/site.ts`).
  - `ArticleSchema` on blog posts and case studies.
  - `BreadcrumbList` on all detail and index pages.
  - `FAQPage` on `/faqs`.
- **Sitemap**: auto-generated at `/sitemap-index.xml` by `@astrojs/sitemap`. Includes all 372 built pages.
- **Canonicals**: derived from `Astro.url` unless explicitly overridden via a `canonical` prop.
- **Locale**: `en_GB` hardcoded in `BaseHead.astro`.

WP-side SEO machinery not migrated: Yoast redirects (live in `wp_redirection_items`) and 404 logs. See §6 below.

## 4. Synthesised content (where the old data didn't have a field)

The new Astro `courses` and `caseStudies` schemas require fields the Next.js intermediate didn't carry. The migration script filled these deterministically:

### 4.1 Course `category` (enum)

The old data had free-text categories like `"Communication Skills Training"`. The new schema requires one of: `sales | communication | presentation | leadership | management | personal-development | specialist | format`.

Mapping table in `scripts/migrate-content.ts → CATEGORY_MAP`. Fallback heuristic looks for substring matches in the old category string.

### 4.2 Course `outcome`, `audience`, `agenda`, `outcomes`

- `outcome` — derived from the first sentence of the old `intro`.
- `summary` — copied verbatim from old `intro`.
- `audience` — generated as `"Professionals looking to develop their skills in <course title lowercased>."` Edit by hand where a more specific audience is known.
- `agenda` — the items array from the old "What You'll Learn" section. Where missing, a 5-item generic agenda was inserted; flag for review.
- `outcomes` — same items, prefixed with `"Confidence and capability in: …"`. Edit for tone where needed.

### 4.3 Case-study `sector` and `courseSlug`

- `sector` — inferred from the old `category` string + `client` name using a keyword heuristic (`scripts/migrate-content.ts → inferSector`). E.g. category contains "law" → sector `"Law"`; client contains "Hilton" → `"Travel"`. Default `"General Business"`.
- `courseSlug` — inferred from the old `category` string by trying close-match slugs (`scripts/migrate-content.ts → inferCourseSlug`). Default `leadership-training` if no match found.

### 4.4 Case-study `publishedDate`

Old data has no date. All 157 newly-migrated case studies have `publishedDate: 2024-01-15`. Edit by hand where the real date is known.

### 4.5 Course mode (`virtual` / `in-person`)

Parsed from the old `format` string. `"Virtual & In-Person"` → `['virtual', 'in-person']`; `"Virtual"` only → `['virtual']`; `"Full day"`/missing → both. See `parseMode()` in the script.

### 4.6 Sector `namedClients[]`, `relevantCourses[]`

Old sector data didn't have these as structured fields (clients were mentioned in prose). Both arrays default to `[]`. Either fill in by hand or extend the sector layout to derive `relevantCourses` from the case-study collection by sector.

`scripts/old-data/` — a snapshot of the prior Next.js TS data files with `import type` lines stripped so `tsx` can execute them. Safe to delete once you're confident the migration is final.
